# BRIGADIR — Рабочий план (внутренний инструмент)

**Это актуальный план работ.** Продукт строится как некоммерческий внутренний инструмент для своей команды. Полный roadmap продукта ([roadmap.md](roadmap.md)) и разделы Phase 2+ в [spec.md](spec.md) — справочный материал «на вырост»; при противоречии приоритет у этого файла.

## Принятые решения (2026-07-10)

1. **Подключение Jira — API token, без OAuth.** В форме создания workspace пользователь вставляет URL сайта + email + API-токен (создаётся на id.atlassian.com); система сразу валидирует его `GET /myself` и читает проект. Храним `expires_at` (токен живёт ≤ 1 года) и предупреждаем заранее. OAuth 3LO с редиректом — возможное будущее улучшение, не в плане.
2. **UI для workspace и агентов — с самого начала** (перенесено из Phase 2 в Phase 1): агентов будет создавать команда, а не один человек. Флоу: создать workspace (визард с подключением Jira, переподключение — в настройках) → внутри workspace список агентов, «+» создаёт агента (имя, инструкция, executor/модель, триггер-статус, целевые статусы).
3. **В Jira пишет только система.** Агент никогда сам не двигает карточку и не комментирует — он репортит через тулзы (`report_progress` / `request_human` / `complete_task`), а BRIGADIR переводит статусы, пишет комменты и создаёт задачи людям. Это правило зашито в обёртку инструкций.
4. **UI-библиотека — Element Plus** (Vue 3 + Vite + Pinia + TanStack Query): самый полный набор admin-компонентов под наши экраны и самая предсказуемая для агентной генерации кода. Kanban-доска — своя (drag-and-drop не нужен: карточки двигает система).

Модель исполнения (подтверждена): один прогон агента = один процесс `claude -p` от начала до конца (внутренний цикл агент крутит сам, «итерации» снаружи не нужны); цепочка агентов — через статусы Jira (агент A завершился → система перевела тикет → новый статус триггерит агента B); агенты друг друга не запускают.

## Что вырезано из полного плана

- Executor'ы `anthropic_api` и `deepseek_api` — абстракция `AgentExecutor` остаётся в коде, реализации добавим при необходимости. Стартуем с `claude_cli` (+ опционально `claude_routines`).
- OAuth 3LO, динамические вебхуки, Forge — токен + поллинг (+ опционально один системный вебхук, если есть админ-права).
- Песочницы (Docker/gVisor), секрет-брокер с egress-прокси — доверенная команда: bare process + git worktree + env-санация.
- Multi-tenant, users/RBAC/SSO, биллинг, аудит, Marketplace — не нужны. Доступ к дашборду — один общий bearer-токен.
- Компилятор behavior→wrapper — один захардкоженный шаблон обёртки; behavior-опции добавим, если реально понадобятся.

## Итерации

Ритм работы: итерация = 0.5–2 дня, размер PR. Каждая: plan mode → одобрение плана (≈5 мин) → автономная реализация с тестами → чекпоинт по DoD. Журнал прогресса — `docs/progress.md` (ведётся автоматически с первой итерации).

| # | Итерация | Содержание | Участие пользователя |
|---|---|---|---|
| 1 | Скелет | Монорепо (backend/worker/contracts), Postgres-миграции, BullMQ-очереди, mock-executor, тесты пайплайна | Одобрить план, взглянуть на схему БД |
| 2 | Jira-ядро | JiraModule (token auth, rate-limiter, per-issue write queue, transition discovery, ADF), поллер `/search/jql` + high-water mark, машина статусов на mock'е | Тестовый Jira-проект + бот-аккаунт + токен |
| 3 | claude_cli | Executor: spawn `claude -p` (stream-json, `--json-schema`, лимиты, kill process group), env-санация, rate-limit-обработка | 15 мин: первый живой прогон на своей подписке |
| 4 | Перенос агентов | 6 агентов по одному переезжают с Jira Automation; упрощённая обёртка инструкций | Промпты агентов, маппинг статусов доски |
| 5 | Callback + отчёты | MCP-сервер (3 тулзы), run JWT, ReportSchema, Stop-hook, скраббер секретов | Одобрить план |
| 6 | UI: workspace и агенты | Визард workspace (URL+email+токен, валидация `/myself`, чтение проекта, `expires_at`+алерт), CRUD агентов, переподключение Jira в настройках | Потыкать флоу создания |
| 7 | UI: доска и human-queue | Доска тикетов, карточка тикета (прогоны, чеклисты ✅/❌, таймлайн, стоимость), страница Tasks с разрешением задач, SSE | Потыкать UI; критерий: боли №2 и №3 закрыты |
| 8+ | По желанию | `claude_routines` executor, Slack-уведомления о human-tasks, статистика, `--resume` вместо нового прогона при ответе человека | — |

Критерии готовности итераций 1–5 — DoD Phase 0 из [roadmap.md](roadmap.md), итераций 6–7 — DoD Phase 1. Детальная спека — [spec.md](spec.md) §0.x–1.x с поправками из этого файла.

## Модель для команды

- Оркестратор — на общей машине/VPS в своей инфре; Jira — выделенный бот-аккаунт (действия агентов атрибутируются боту).
- Исполнение: старт — подписка Max владельца на его машине (личный пайплайн); для общего командного раннера — командный API-ключ Anthropic со spend cap (~$0.5–2/прогон на Sonnet 5).
